## 二、链接这一步抓出来的四个真问题

这四个都是 **`-fsyntax-only` 永远发现不了**的。这才是做链接探针的意义。

### 问题 1（最要命）：`clock_gettime_nsec_np` 会静默算错

| 项 | 内容 |
|---|---|
| 是什么 | 苹果独有的函数：直接返回纳秒的 64 位时钟 |
| 在哪 | **4 个宿主文件**：`dm_bossrush.c`、`dm_textbox.c`、`hle_fs.c`、`hle_time.c` |
| 为什么之前没发现 | 它靠苹果的 `<time.h>` "顺带声明"，**按头文件普查根本数不到** |
| 为什么最要命 | **不声明也能编过**（C 只给警告），而编译器会**默认它返回 `int`** ⇒ 64 位纳秒值被**静默截断到 32 位**。时间计算会莫名其妙地错，而且没有任何报错 |
| 处置 | ✅ 已补垫片，**且真的实现**（不是空壳）：`src/dm_compat_mach.c` |

> 这一类是"最坏的一类 bug"：不报错、不崩溃、结果错。**必须靠链接探针抓，靠编译抓不到。**

### 问题 2：`entry.S` 用的是苹果的符号命名约定

`entry.S` 里定义的是 `_unimpl_stubs`、`_dm_gate`、`_dm_thread_enter`——**带一个前导下划线**。
那是 **Mach-O（苹果）的约定**（苹果会自动加下划线）；**ELF（鸿蒙）上没有这个下划线**，
C 代码要的是 `unimpl_stubs`、`dm_gate`……于是 7 个符号**全部对不上**。

处置：✅ 加了按平台的 `CSYM()` 宏，**正文的汇编指令一个字没改**：

```asm
#if defined(__OHOS__)
#define CSYM(x) x          // ELF：C 符号没有下划线
#else
#define CSYM(x) _##x       // Mach-O：带下划线
#endif
```

苹果侧展开结果与改动前**逐字符相同**。

### 问题 3：`pthread_get_stackaddr_np` 两边的口径相反

苹果返回的是**栈顶**（高地址），Linux 的 `pthread_attr_getstack` 给的是**栈底**（低地址）。
差一个换算。`hle_svc.c` 拿这组值去框"某个地址在不在当前线程的栈上"——
**口径错了它会把栈上的地址当成代码页**，回答给 SDK 的内存信息就是错的。

处置：✅ 已补垫片，并做了 `低地址 + 大小 = 栈顶` 的换算（`src/dm_compat_mach.c`）。

### 问题 4：`ld.lld` 默认只报 20 条错误（差点让我得出完全错的结论）

第一次跑链接时，输出是"20 个未解析符号"。看着挺乐观——
翻到最后才发现一行：

```
ld.lld: error: too many errors emitted, stopping now (use --error-limit=0 to see all errors)
```

**关掉上限后，真实数字是 74。** 处置：✅ 脚本里加了 `-Wl,--error-limit=0`。

> 记这一条是因为它是**方法论问题**：工具给的数字不等于全部真相，
> 尤其是"看起来正好是个整数"的时候，要去翻原始日志。

## 三、顺带搞清楚的两件事

### 3.1 触摸控制模块**不用移植**，只要编进来

上游把它放在 `dm/ios/Sources/dm_touch_controls.c`，名字看着像 iOS 专用。
但它只包含：

```c
#include "dm_touch_controls.h"
#include "../../host/dm_input.h"
#include <math.h> <string.h> <stdatomic.h>
```

**是平台无关的 .c，实测在鸿蒙侧原样编过。** 所以那 22 个 `dm_tc_*` 符号直接就有了。

### 3.2 `touch_mac.c` 不该编（是我一开始加错了）

它是 macOS 的触摸前端，上游的方案里本来就写明"鸿蒙侧不编这些文件"。
一开始我把它加进链接集，于是冒出 22 个 `dm_tc_*` 未解析——**那是我造成的假缺口**。
排除后数字才收敛。记这一条是为了说明：**缺口清单也要复核来源，不能拿来就用。**
