# 便携性验证样本（刁难样本集）

> 建立：2026-10-14 ｜ 入口：`bash dm/ohos/tools/portable_check.sh` ｜ 四条断言全过

---

## 一、这是什么

**不是拿来用的程序**，是拿来**验证 L1（垫片层 + 探针工具）真的通用**的样本。

起因：`PORTABLE.md` 里写着"通用层换一个项目不用动"——但那句话当时是**推理出来的**，不是验证出来的。
这个样本就是来验证它的。

它**故意与 d2r-mobile 长得不一样**：

| 故意制造的差异 | 打的是哪个假设 |
|---|---|
| 目录**嵌套三层**（`src/platform/`、`src/fs/`、`src/crypto/`…），而 d2r-mobile 的源码是平铺的 | 工具的"只扫一层"假设 |
| 只用一个 include 根，头文件自己带目录结构 | 工具的 include 路径假设 |
| 自己带一份 `probe.conf` | "配置能不能属于另一个项目" |
| 用了一大片苹果专有 API，但**换一种写法** | 垫片的**覆盖率**（不是只覆盖 d2r-mobile 用到的那几样） |

## 二、目录与期望结果

```
demoapp/
├── probe.conf              ← 它自己的探针配置（本身也是被测对象）
├── include/demoapp.h
├── src/                    ← **期望：8 个文件全部编过**
│   ├── platform/clock.c        时钟（mach + clock_gettime_nsec_np）
│   ├── platform/sync.c         GCD 信号量 + qos + 栈信息
│   ├── platform/memory.c       安全读内存 / 内存统计 / malloc 统计 / sysctl
│   ├── fs/path.c               克隆 / 原子改名 / 扩展属性 / 刷指令缓存
│   ├── fs/text.c               strlcpy/strlcat/arc4random/memmem
│   ├── crypto/hash.c           CommonCrypto 的 MD5 / SHA-1 / SHA-256
│   ├── app/report.c            纯标准库（对照："平台无关的部分一行不用改"）
│   └── entry/main.c
└── gaps/                   ← **期望：探针报出缺口**（反向验证）
    ├── no_oslog.c                   `<os/log.h>` 没垫
    ├── no_security.c                `<Security/SecRandom.h>` 没垫
    ├── no_hmac.c                    CommonCrypto 只垫了 Digest、没垫 HMAC
    ├── no_libproc.c                 `<libproc.h>` 没垫
    └── undeclared_sysctlbyname.c    ⭐ **编得过，但符号不存在**（见下）
```

**`gaps/` 是"反向验证"**：如果探针在这里报"全过"，坏的不是样本，是**探针**（漏检）——那比缺垫片更糟。

## 三、实测结果（2026-10-14）

```
✅ A. 本项目编译探针：0 失败（没被改坏）
✅ B. 样本 src/：8 个文件全过
✅ C. 样本 gaps/：编译探针报出 4 个缺口
✅ D. 样本 gaps/：链接探针抓出了编译探针放过的那一个
```

### ⭐ 最有价值的是 D 那一条

`gaps/undeclared_sysctlbyname.c` 用了 `sysctlbyname`（苹果 `<sys/sysctl.h>` 里有声明，
我们的垫片只垫了 `sysctl`，没声明它）。结果：

| 探针 | 结果 |
|---|---|
| **编译探针** | **通过**（C 只给警告 "call to undeclared function"，不报错） |
| **链接探针** | ❌ 报出 `sysctlbyname ← undeclared_sysctlbyname` |

**这正是当初那个真 bug 的形状**：`clock_gettime_nsec_np` 有 4 个文件在用、不声明也能编过、
而编译器默认它返回 `int` ⇒ **64 位纳秒被静默截断**。

所以这一条不是一个"测试用例"，它是**"为什么必须做链接探针"的活证据**：
两个探针**互相不可替代**——编译探针管"每个文件自己讲得通"，链接探针管"文件之间喊的名字对不对"。

## 四、这次验证出来的、和**没**验证出来的

**验证出来的**（可以当结论用了）：

- 垫片层的**机制**（同名头抢注 + include 顺序）对另一个项目成立；
- 垫片层的**覆盖面**能支撑一个用它用得挺杂的项目（那份样本碰了 8 类 API）；
- 探针工具能做到：**指向别的项目**、**读别的项目的配置**、**扫嵌套目录**、**分清"垫片来自 L1、源码来自项目"** 两个根。

**没验证出来的**（别当成已完成）：

1. **只到了"能编译 + 能链接"这一层，"跑起来"没验。** 见 `PORTABLE.md` 第五节。
2. **样本是我们自己写的**——它只能测"我们想得到的依赖"，**测不出"面对陌生代码时的判断成本"**，
   也测不出"第二次到底省了多少力"。那两条只有拿一个**真的、别人写的项目**跑一遍才能得到。
3. 样本不走真实构建链（没进 HAP、没上真机）。

**换句话说**：这份样本把"通用"从**推理**推到了**部分验证**，但**不是全部验证**。
诚实的说法是：**编译与链接这一层的通用性有了证据；整条链的通用性还只是有依据的假设。**

## 五、顺带抓到的一个工具缺陷（值得记住）

做这个样本时，我把源码发现从"只扫一层"改成递归，**本项目自己的数字当场从 67 跳到 98**——
因为多扫进了 `dm/host/tests/` 下的单测。

那个"只扫一层"的假设**从来没写在任何地方**，它在下一次改动里静默失效了。
处置：不偷偷改行为，而是加显式开关 `DM_RECURSE`（缺省 0 = 原行为）。

**教训**：隐含假设不写下来，就会在某次无关的改动里静默变味——这正是"换项目"测试的价值。
