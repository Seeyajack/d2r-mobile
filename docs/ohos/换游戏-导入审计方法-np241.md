# 换游戏的第一件事：导入审计（np241）

> 适用：把宿主 + 引擎接到一款**新游戏**上，还没出画面之前。  
> 目的：在真机之前就把「哪些导入会落空」算清楚，而不是一轮一轮试。

## 为什么需要

宿主的 `resolve_import`（`dm/host/hle.c`）只有两条路：

1. 查 `swhle` 段（= 各 `hle_*.c` 的 `HLE`/`HLE_FORCE` 条目 + `hle_table.c` 的 libc 直通表）；
2. 查不到 ⇒ 发一个**未实现桩，调用恒返回 0**。

客体把 0 当指针用就 SIGSEGV。所以「宿主缺的导入清单」= **未来的崩溃点列表**，  
划掉一条就前进一步，这是「离出画面还有多远」唯一可量化的指标。

## 两个工具

```bash
# ① 槽 → 名字：崩溃回溯给出桩地址时，翻译成是哪个导入
python dm/gfx/tools/import_slots.py <模块.patched.bin>                 # 全表
python dm/gfx/tools/import_slots.py <模块.patched.bin> --stub 0x34f374 # 反汇编桩，自动算槽再查名
python dm/gfx/tools/import_slots.py <模块.patched.bin> 0x6c1b20        # 直接查槽

# ② 缺口清单：客体要、宿主没有
python dm/gfx/tools/import_audit.py <main.patched.bin> <sdk.patched.bin> <dm 源码目录> --tsv gap.tsv
```

`import_slots.py` 复刻宿主的定位规则：NSO 头 +4 → MOD0 偏移；MOD0+4 → 动态段偏移；  
动态段里取 `DT_SYMTAB/STRTAB/RELA/JMPREL`；每条 `Elf64_Rela.r_offset` 就是模块内地址  
（NSO 段 1:1 映射，等于文件偏移）；`r_info>>32` 是符号下标。

## 判读要点（BotW 实测）

**① 先确认「装了几个模块」——这一条最容易被忽略，也最致命。**

BotW 把系统库拆成多个 subsdk，`main` 的 14 条强引用导入分别由它们提供：

| 导入                                                                                                                               | 由谁定义        |
| -------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| `nn::vi::Initialize` / `OpenDefaultDisplay` / `CreateLayer` / `SetLayerScalingMode` / `GetDisplayVsyncEvent` / `GetNativeWindow` | **subsdk1** |
| `nv::InitializeGraphics` / `nv::SetGraphicsAllocator` / `SetGraphicsDevtoolsAllocator一会直接读日志就行，没有你再自己点`                          | **subsdk0** |
| `movie::Decoder`（3 参构造）/ `Buffer::Size` / `Buffer::Offset` / `MediaData::Clear` / `FindRect`                                     | **subsdk3** |

只装 `main+sdk` 时这 14 条全部落空（返回 0）；**装全六模块后强引用缺口归零**  
（余下只有弱引用 `glslc*` 与 rtld 提供的 `__rel_*` 链接符号，返回 0 是预期）。  
`MAX_MOD = 8`，rtld 不装（宿主自己扮演 rtld）。

**② 名字对不上 = 未命中。** `movie::Decoder` 在宿主里只有 **4 参**版本  
（`...DecoderModeEi`），BotW 要的是 **3 参**版本（`...DecoderOutputFormatE`）——  
mangled name 差一截就落空。审计报出来的名字要**逐字**比对宿主条目，不要凭"看起来一样"。

**③ 别把「本模块定义」误当导入。** `newlocale` / `__cxa_guard_acquire` / `memset`  
在 sdk 里都是 `st_shndx != 0`（本模块定义）；`calloc`/`malloc`/`free` 在 sdk 里未定义、  
由 **main** 提供。判据看 `st_shndx`（0 = 未定义）。

**④ 弱引用不算雷。** `st_info >> 4 == 2`（STB_WEAK）的返回 0 是设计意图，单列。

## 反面的教训（我踩过，别再踩）

**不要改「看起来像检查」的函数来绕过崩溃。** BotW 的 `sdk+0x349ce4` 我一度当它是  
"locale 检查"改成恒返回 0，结果崩点只是从 `memset(-1)` 挪到 `ldr x0,[x0]`——  
因为它其实是 **`__cxa_guard_acquire`**，改它等于宣布**所有**惰性单例已构造好，  
`locale::__global()` 于是返回一块全零内存。

正确做法：**先用 `import_slots.py --stub` 把桩翻译成名字**，确认它到底是谁，再决定。

## 收尾检查

```bash
# 每个模块的未决项应为 0（文件里 "# 共 N 处" 那一行）
grep "共 " <out>/*.unresolved.tsv
```

BotW：main/sdk/subsdk0-2 均为 0；subsdk3 有 2 处 `br x18` 未识别，形态是  
`ldrsw x13,[x10,x18,lsl#2]; add x18,x13,x10; br x18` —— 32 位自相对偏移跳转表，  
不需要重定位，属良性（已记录待真机复核）。
